# okfctl—`migrate`: a two-phase v0.1 → v0.2 upgrade path

**Status:** Approved (design) · **Owner:** Casey West · **License:** Apache-2.0
**Source of truth:** OKF `SPEC.md` **Version 0.2** (authoritative upstream:
`GoogleCloudPlatform/knowledge-catalog/blob/main/okf/SPEC.md`)—§5.1 `sources`,
§5.2 `generated`, §6 paths, §7 actor convention, §8 index files, §11 permissive
conformance, §12 versioning, §13.1 breaking renames.
**Base:** `main` @ `75df8a6` (v0.2 reader, PR #45) **Branch:** `wt/t_f327a4b6`

## Problem

okfctl now *reads* v0.2 (PR #45) with v0.1 fallbacks, but a bundle author has no
supported way to *move* a bundle from v0.1 to v0.2. Hand-editing 218 nodes is not
a path. §13.1 defines exactly two breaking renames a migration must apply:

1. `timestamp` → `generated.at` (with `generated.by` an actor per §7).
2. body `# Citations` list → frontmatter `sources` entries (`resource` per item).

Plus the version markers: the `.okf` sidecar `okf_version` and the bundle-root
`index.md` marker (§8/§12—the only place index frontmatter is permitted).

## The governing constraint (Casey, ADR on the card): the LLM lives BESIDE the tool

`okfctl` ships to strangers who have a bundle and nothing else—no team, no
kanban, no API credentials. So `migrate` MUST be **two-phase, consumer-agnostic**
and MUST NOT acquire a model/network/credential dependency on any path:

    okfctl migrate --plan  <bundle>                     # writes migrate-plan.json
    okfctl migrate --apply <bundle> --plan migrate-plan.json

- Phase 1 (`--plan`) is PURE READ: it computes every deterministic edit and
  enumerates every judgment item with enough context to resolve it later. It
  writes only `migrate-plan.json` (never a node).
- Phase 2 (`--apply`) reads the plan back, applies the deterministic edits plus
  any judgment decisions the plan file now carries, and re-validates.
- The plan file's CONSUMER is deliberately unspecified (agent, chat, colleague,
  shell loop, human editor). The tool MUST NOT care and MUST NOT detect. A
  judgment item is NEVER "solved" by reaching for an LLM inside the tool; if it
  can't be resolved deterministically it stays in the plan.

## Measured corpus reality (real `~/src/knowledge-base/bundles/knowledge`)

- **0 nodes carry a `timestamp` field**—the corpus already uses
  `created`/`modified`. The §13.1 `timestamp` rename is spec-mandated and
  implemented for correctness, but is a **no-op on this corpus**.
- **218 nodes carry a body `# Citations` list**; most items are numbered `[1]`
  prose *evidence findings* (VERIFIED/NUANCED), not URL sources. `resource` is
  REQUIRED per §5.1 `sources` entry, so a prose-only finding cannot be forced
  into `sources` without FABRICATING a resource—the one thing this migration
  must never do.

## The deterministic ↔ judgment split

**Deterministic (applied in code, no judgment):**

- `timestamp` → `generated { by, at }`. `generated.at` = the legacy timestamp
  value verbatim. `generated.by` = the explicit `--generated-by <actor>` (§7
  form). §13.1/§7: if `--generated-by` is not supplied AND no actor is inferable,
  this is NOT deterministic—the whole node's timestamp rename becomes a
  **judgment item** (report and skip; never guess provenance).
- `# Citations` items that carry a resolvable resource → `sources[].resource`,
  order preserved. A URL-bearing item yields `resource: <url>`; an item that is
  already a bundle-relative link keeps its relative form (§6). Order is the body
  order.
- `.okf` sidecar `okf_version` → `0.2`; bundle-root `index.md` `okf_version`
  marker → `0.2` (§8/§12).

**Judgment (enumerated in the plan, never guessed):**

- Any `# Citations` item with no follow-able resource (a prose finding). Emitted
  with node path, item index, and the verbatim item text as `context`, so the
  plan's consumer can supply a `resource` (or reclassify to `verified[]`) or drop
  it. The tool never invents a resource.
- Any node whose `timestamp` rename lacks an actor (no `--generated-by`, none
  inferable). Emitted so the consumer supplies `generated.by`.

## Non-negotiable properties (house style: `mutate.go` / `frontmatter_edit.go`)

- **`--apply` dry-run byte-identical to the real `--apply`**—same property PR
  #38 gated on. The tree hash after a dry-run apply equals the pre-run hash; the
  planned edits printed match the applied bytes.
- **Idempotent**—a second `--plan`+`--apply` cycle is a zero-diff no-op.
- **Order-preserving** frontmatter edits via the single order-preserving writer
  (`yaml.Node` round-trip, as `TouchModifiedFile` does). No key reordering, no
  comment stripping.
- **Additive only**—never drop an unrecognized frontmatter key (§11 forbids
  rejecting them; a migrator that discards them is strictly worse than one that
  ignores them). The rename removes exactly `timestamp` and adds `generated`;
  every other key survives in place.
- **Negative control**—running against an already-v0.2 bundle changes nothing.

## Shape

- `internal/okf/migrate.go`—pure plan/apply core (no cobra, no network):
  `MigratePlan(b) (Plan, error)`, `Plan` (JSON-serializable: deterministic edits
  + judgment items + version bumps), `MigrateApply(root, b, Plan) error`. Reuses
  the order-preserving frontmatter writer and `citation`/link scanners already in
  the package.
- `cmd/migrate.go`—`okfctl migrate --plan|--apply` wiring, `--generated-by`,
  `--dry-run` (on `--apply`), `--plan <path>` (default `migrate-plan.json`).

## Done when

- v0.1 fixture → `migrate --plan` then `--apply` produces a bundle that validates
  clean AS v0.2.
- `--apply` dry-run byte-identical to the applied run (test).
- Idempotent: second cycle zero diff (test).
- Unrecognized keys survive round-trip (test)—additive-only.
- Negative control: already-v0.2 bundle unchanged (test).
- Dry-run exercised against a COPY of the real corpus; counts pinned in the PR.
